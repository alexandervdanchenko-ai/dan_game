# Первый замер с отрисовкой — 21 ноября 2026

Замер сделан поверх коммита `cf10256` с временной графикой. Запуск из проекта движком Godot 4.5.1 Standard, Windows, Compatibility через ANGLE/D3D11, Intel HD Graphics 520, драйвер 26.20.100.7261. Фактический размер окна 1370×749. Запрошенные 1920×1080 в проверенной оконной сессии недоступны. Два запуска по 5 секунд на сцену.

| Сцена | p95, прогон 1 | p95, прогон 2 | Самый длинный кадр, прогоны 1 / 2 |
| --- | ---: | ---: | ---: |
| Пристань | 18.65 мс | 18.32 мс | 4038.34 / 3602.35 мс |
| Наземный бой | 18.54 мс | 18.67 мс | 19.45 / 19.64 мс |
| Абордаж | 18.33 мс | 18.20 мс | 19.40 / 19.11 мс |

В каждом прогоне на пристани был один кадр свыше 50 мс. В двух боевых сценах таких кадров не было. От вызова перехода на палубу до следующего `process_frame` прошло 26,17 и 26,36 мс. Это время вызова и ожидания следующего игрового кадра; отдельно GPU не измерялся.

Длинный начальный кадр воспроизвёлся, а p95 во всех сценах выше 16,7 мс. Godot в обоих запусках сообщил о невозможности создать кэш шейдеров. Чтобы установить причину, требуется повторить замеры с доступным кэшем и раздельно проверить первый показ воды, материалов и интерфейса. Этот короткий замер в проекте служит диагностикой. Приёмка по плану требует экспортированной сборки, установленного целевого оборудования, 1080p и представительной графики.

Повтор: `godot --path . --script res://tools/benchmark.gd -- --seconds=5`. Без параметра сценарий длится по 120 секунд на сцену. Заключительная строка JSON содержит фактический размер окна, дисплей, адаптер, p50, p95, максимум и счётчики длинных кадров. Режим `--headless` годится для проверки сценария и исключается из сравнения графической производительности.
